# 装机守卫（②）设计

> 建立在 0.9.0 的进程归属监控引擎（①）之上。用户原话："在所有应用安装的时候都要进行监控，一旦有异常行为会标红报告给用户（包括疑似捆绑，最好能将捆绑的软件全部去掉，只留需要的），代表软件金山打字通、360 等。千万不要在我的本地跑这些捆绑。"
> 用户明确说"直接整，不要问我"，所以下面带【我的决定】的取舍由实现方拍板，用户事后可推翻。

## 目的
装软件时自动看着它，装完告诉用户：它装了几个程序（有没有捆绑）、做了哪些越界的事（开机自启、改浏览器、装证书……），并能一键把捆绑进来的程序干净地去掉，只留下用户要的那个。

## 目标
1. **自动监控所有安装**（可选、默认关）：开启"装机守卫"后，用户照常双击安装包，守卫自动识别并监控，不需要先到设置页点按钮。
2. **标红报告**：每次安装结束后生成一份报告，列出发现的问题，按严重程度分红 / 黄两档，每条一句中文说明为什么值得注意。
3. **识别捆绑**：把这次安装新增的东西按"属于哪个程序"分组，指出哪些是捆绑进来的。
4. **去掉捆绑**：对捆绑的程序一键卸载并清理残留，删除前备份、可恢复；用户要的那个程序不动。

## 非目标（本期不做）
- 安装过程中拦截、阻止捆绑（只事后处理）。
- 识别病毒木马（这是杀毒软件的事；我们只看"装了什么、改了什么"）。
- 网络行为监控。
- 对安装后长期运行的行为做追踪（→ ③）。

## 反目标（技术上跑通也算失败）
- 把用户原有的文件或用户要的那个程序的文件当成捆绑删掉。
- 守卫常驻后明显拖慢电脑或影响游戏，或触发反作弊。
- 守卫开着时用户不知道它开着（必须能看到状态、随时能关）。
- 在用户主力机上跑真捆绑安装包做测试——**所有真捆绑软件只在 VirtualBox 测试虚拟机里跑**。

## 约束
- 沿用 ① 的全部安全不变量：提权助手只接受结构化请求，不执行请求里给的任意路径；足迹存受保护区；删除走 0.8.0 卸载器的"助手自扫∩用户勾选 + 备份 + 可恢复"。
- 与游戏反作弊共存：只用 ① 已验证可共存的 ETW 清单提供程序，不开 Hyper-V、不装驱动。
- 轻量版不受影响：守卫是可选模块，关着时没有任何常驻进程。
- 全中文界面与文案。

## 设计

### 1. 自动发现安装（守卫常驻模式）
【我的决定】守卫开启时，提权助手常驻，只订阅 Kernel-Process 的进程起止事件（全系统每分钟也就几十个，开销可忽略）。每个新进程用"是不是安装程序"的判定：
- 映像是 `msiexec.exe` 且命令行带 `/i` 或 `/package`；
- 或 PE 版本信息 / 文件名呈现安装程序特征（文件名含 setup / install / 安装，或版本信息里出现 Installer / Setup，或是常见安装框架：NSIS、Inno Setup、InstallShield、WiX Burn、Advanced Installer——按 PE 里的特征串识别）；
- 并且是用户会话里由 explorer / 浏览器 / 下载工具启动的（排除系统维护、Windows 更新、我们自己的 winget 更新）。

判定为安装程序后，立刻以它的 PID 为根开启一次 ① 的足迹会话（同一时间只监控一个；第二个安装在第一个结束前开始，则记为同一会话里的另一个根，或排队并在报告里说明）。
- 这样会漏掉安装程序启动后、会话就绪前的一小段（通常几百毫秒，安装程序此时多在解压自身到临时目录）。足迹完整性里如实写"安装程序启动约 N 毫秒后才开始监控"。
- 设置页原有的"选择安装程序并监控…"保留：它走两阶段握手，没有这段缺口。

### 2. 足迹补充：进程表
【我的决定】`MonitorFootprint` 增加这次会话里树内进程的列表（PID、父 PID、映像路径、启动时间、签名者）。分组和"谁启动了谁"都需要它；足迹条目已有创建者 PID。

### 3. 按程序分组，识别捆绑
- **程序** = 这次安装新增的每个卸载登记键（`...\Uninstall\<子键>`，HKLM 与 HKCU、含 WOW6432Node），从键里读出显示名、发行商、安装位置、卸载命令。
- 每条足迹条目归到哪个程序，按顺序判：
  1. 路径落在某个程序的安装位置之下；
  2. 由创建了该程序卸载登记的那个进程（及其子进程）写的；
  3. 都不满足：归入"未归类"，不参与自动删除。
- **主程序**：根安装进程自己（不经子安装程序）创建的那个卸载登记；有多个时取显示名或发行商与安装包签名者 / 文件名最接近的。用户可以在报告里改选"我要的是这个"。
- **捆绑**：除主程序外的每个新增程序。另外，安装过程中启动的**另一个安装程序**（子进程本身被判为安装程序，且签名者与主安装包不同）即使没留下卸载登记，也标红"运行了另一个安装程序"。

### 4. 异常规则（Core 纯逻辑，可单测）
输入足迹（+ 分组结果），输出 `Finding(严重度, 类别, 说明, 相关条目)`。【我的决定】首批规则：

| 类别 | 判定 | 严重度 |
|---|---|---|
| 捆绑安装 | 新增卸载登记 > 1，或运行了签名者不同的子安装程序 | 红 |
| 根证书 | 写入 `...\SystemCertificates\ROOT\Certificates\` 或 `AuthRoot` | 红 |
| 浏览器劫持 | 改 IE/Edge/Chrome 主页、默认搜索；写浏览器策略 `ExtensionInstallForcelist` / `HomepageLocation` 等 | 红 |
| hosts | 改 `drivers\etc\hosts` | 红 |
| 可移动盘 | 在可移动卷（带卷序列号）根目录建文件 / 目录 | 红 |
| 开机自启 | 新增 Run / RunOnce 值、启动文件夹快捷方式、计划任务、自动启动的服务 / 驱动 | 黄（属于捆绑程序的升为红） |
| 越界写入 | 写进别的已安装软件的安装目录，或 `C:\Windows`、`System32` | 黄 |
| 桌面图标 | 在公共或当前用户桌面新建快捷方式且不属于主程序 | 黄 |
| 文件关联 | 改常见扩展名的默认打开方式（UserChoice 之外的 Classes 关联） | 黄 |

"可能"档的条目参与规则，但报告里注明"可能不是它干的"。

### 5. 去掉捆绑
【我的决定】复用 0.8.0 卸载器，不新造删除逻辑：
1. 对选中的捆绑程序，按它的卸载登记调用 0.8.0 的卸载流程（先跑它自带的卸载程序；机器级走后台助手）。
2. 残留清单改由足迹给出：只取归到这个程序、"确定"档、`IsNew=true` 的条目，作为预勾选；"可能"档列出但不预勾选。
3. 删除仍走"助手自扫 ∩ 用户勾选 + 备份 + 可在历史恢复"。足迹只决定预勾选，不绕过卸载器的安全检查。
4. 主程序和"未归类"条目永远不预勾选。

### 6. 界面
- 新增导航页"装机守卫"：顶部开关和状态（开 / 关、正在监控谁）；下面是安装记录列表（来自足迹存储），每条显示安装包名、时间、红黄问题数。
- 点开一条：分组显示"主程序 / 捆绑程序 / 未归类"，每组下列出条目；问题列表红黄着色；捆绑程序旁边有"卸载这个捆绑软件"。
- 一次安装结束、发现红色问题时，弹 Windows 通知："××安装时顺带装了 2 个程序"，点开直达报告。
- 设置页原有的"监控安装"区域改为指向这个页面。

## 测试
- 规则、分组、安装程序判定都是 Core 纯逻辑，用构造的足迹单测。
- **真实捆绑软件只在虚拟机测**：VirtualBox 里的 Win11 23H2 测试机（NAT 网络、关剪贴板和拖放、只读共享文件夹传程序进去、干净快照，每测完一个回滚）。样本：金山打字通、360 系列等典型捆绑安装包；对照组：7-Zip、Notepad++、VS Code 等正常安装包——对照组不应出现红色问题。
- 验收：捆绑样本能识别出捆绑并正确分组；对照组零误报红；"去掉捆绑"后主程序仍能正常启动、捆绑程序及其自启项 / 服务 / 计划任务消失，且可从历史恢复。

## 留给实现者

- 规则表的具体键路径清单。
