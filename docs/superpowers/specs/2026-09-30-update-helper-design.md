- 日期：2026-09-30
- 状态：待审阅

## 1. 背景与目标

电脑没有手机那样统一的应用商店，很多软件靠浏览器下载，各自更新、各自弹窗；现有的"软件管家"大多是安全软件的附属功能，而且带广告和捆绑。

本软件的定位：**纯净无广告、懂国产软件、把"稳"放在第一位的 Windows 软件管家**。与 UniGetUI 等工具的区别是：我们替用户判断风险，而不是把所有更新平铺出来让用户自己判断。

发展路线：自己和亲友使用 → 公开发布 → 长期运营。第一期要小而可用，底层要为后两个阶段留出扩展空间。

### 实测依据（开发者本机，2026-09-29）
- 注册表卸载信息共 297 条，其中 146 条是隐藏的（大多是 NVIDIA CUDA、Python、Intel 的子组件）；控制面板中只显示 149 个软件
- winget 能认出其中约 77 个，约 55 个有新版本；约 36 个国产软件中认出约 22 个
- winget 认不出：WPS、迅雷、火绒、UU 加速器、WeGame、雷电模拟器、EV 录屏等
- 风险案例：微信被识别成两条（3.9 和 4.1）；Anaconda 2022→2026、VirtualBox 7.0→7.2、Docker 4.46→4.93 这类大跨度更新
- 57 个第三方服务（其中 12 个是各家的更新程序）、18 个开机自启项、29 个第三方计划任务
- 装了火绒以后 Defender 处于关闭状态
- 国内网络下，winget 第一次刷新索引用了 4 分钟以上

## 2. 范围

| 期 | 内容 |

| 第二期 | 应用商店、换机一键装回、版本回退、扩充可疑行为规则库、安装足迹记录（精确卸载） |

## 3. 总体架构

```
【用户电脑】
  App（WPF 主程序 + 托盘）  普通权限，常驻托盘（可在设置中关闭）
  Core（核心库，不含界面）
    ├─ Scanner      扫描：软件 / 服务 / 自启项 / 计划任务，归组、分类、解释
    ├─ Judge        判断层：风险等级、观察期、用户例外
    ├─ Updater      更新：winget 官方接口 + 补充库安装器
    ├─ Uninstaller  卸载：官方卸载 → 扫描残留 → 勾选 → 备份后删除
    ├─ Security     查询安全中心、调用 Defender
    ├─ Rules        YAML 规则解析、订阅、验签、合并
    └─ Store        SQLite：扫描结果、历史、设置、备份索引
  Agent（管理员执行器）       由安装时注册的"最高权限计划任务"启动，执行安装和卸载
【云端】
  官方规则仓库（GitHub + 国内镜像）   YAML 规则 + CI 每日检查最新版本并签名发布
  winget 公共软件库（微软）
```

### 技术选型
- C# / .NET 10（LTS，支持到 2028 年）+ WPF + WPF-UI 4.x（Fluent 风格，支持 net10.0-windows）
- winget：NuGet `Microsoft.WindowsPackageManager.ComInterop`（1.29.x）。管理员进程必须使用 `WindowsPackageManagerElevatedFactory`，普通进程使用标准工厂
- 本地存储：SQLite；规则：YAML（YamlDotNet）
- 支持的系统：Windows 10 1809 及以上、Windows 11。没有 winget 时：提示安装 App Installer；这种情况下补充库里的软件仍然可以正常管理

### 权限模型
- App 和托盘以普通权限运行
- 安装本软件时（授权一次）注册一个"以最高权限运行、登录用户身份"的计划任务，用来启动 Agent。App 通过这个任务把需要管理员权限的操作交给 Agent，平时不再弹管理员确认框
- 以登录用户身份（而不是 SYSTEM）运行，才能正确处理"只给当前用户安装"的软件
- App 和 Agent 之间只传递结构化指令（操作类型 + 软件 ID + 参数），Agent 会重新校验规则和签名，不执行任意命令

## 4. 深度扫描

### 扫描来源
| 来源 | 说明 |
|---|---|
| 注册表 Uninstall（HKLM、HKLM\WOW6432Node、HKCU） | 包括 `SystemComponent=1` 的隐藏条目 |
| MSIX / 应用商店软件 | PackageManager API |
| winget 对照 | 给每个软件配上 winget 中的包 ID 和最新版本 |
| 服务、Run 键、启动文件夹、计划任务 | 常驻进程、更新程序、守护进程 |
| 开始菜单和桌面快捷方式、正在运行的进程 | 尽量找出没有登记信息的绿色软件（尽力而为） |

### 整理
- **归组**：隐藏子组件、服务、计划任务挂到所属软件下面。依据的优先级：规则中明确指定 > 安装位置 > 发布者 + 名称前缀
- **分类**：普通软件 / 开发工具 / 游戏 / 运行库 / 驱动 / 系统组件。默认只展示前两类
- **解释**：每个后台项目一句话说明，来自规则；没有规则的显示"未知用途，来自 <发布者>"
- 损坏的条目（比如名称是 `${{arpDisplayName}}` 的）标记为"信息不完整"

## 5. 判断层

| 等级 | 条件 | 行为 |
|---|---|---|
| 低风险 | 版本号的主版本号不变，且已过观察期 | 分级自动模式下，空闲时自动安装 |
| 需确认 | 主版本号变化，或者跨度超过规则中设定的阈值，或者规则标记为 `careful` | 只提醒 |
| 不自动 | 识别存疑（同一个软件对应多个登记条目）、签名或指纹校验失败、多版本共存的运行库、规则标记为 `never-auto` | 任何模式都不自动安装，并显示原因 |
| 不管 | 游戏、由平台自行更新的软件、用户锁定的软件 | 不出现在更新列表中 |

- **观察期**：新版本第一次被发现（本地记录时间）后，先等 N 天再进入自动安装。只在"托管自动更新"开启时生效，默认 3 天，可以在设置中修改；规则可以标记紧急安全更新，跳过观察期
- **版本比较**：兼容 winget 的写法（`< 3.10.8`、`> 1.8.10`），以及 `2021.3.45f2c1`、`2026.07-1` 这类格式；无法比较的版本号一律归为"不自动"
- **用户例外**：可以单独为某个软件设置模式（自动 / 只提醒 / 锁定），也可以"忽略这个版本"

## 6. 更新器

### 模式（用户自选）
只提醒（**默认**）/ 分级自动 / 全部自动 / 打开才检查。"打开才检查"模式下不注册定时检查，托盘也不做后台检查。

- 只提醒：通知"有 N 个更新"，**点击通知就等于同意**，随后自动全部装完
- 设置页和首页都可以直接切换模式

### 一次更新的流程
1. **检查**：winget 的包核对指纹；补充库的包核对 Authenticode 签名，签名者必须和规则中的 `signer` 一致；安装范围（用户级 / 机器级）与原来保持一致
2. **下载**（与安装分开进行）：winget 的包用官方接口下载，补充库的包用 BITS 下载。旧版安装包放进本地缓存（设上限，满了先清最旧的），给第二期的回退功能预留
3. **安装**：静默安装。软件正在运行时，任何模式都不会强制关闭，而是放进"等你确认"列表，通知中提供"关闭并更新"
4. **核对**：重新读取版本号，版本没变就算失败
5. **收尾**：写入历史记录；安装批量更新或"需确认"等级的更新前，可选择创建系统还原点

### 不打扰规则（防卡顿，三层）
1. **以下场景完全暂停下载和安装**（已下载的部分保留，之后断点续传）：有程序全屏运行；规则中列出的游戏或游戏平台进程正在运行；会议软件正在运行且麦克风或摄像头在使用中
2. **平时自动让路**：下载使用 BITS 低优先级，前台一有网络活动就自动降速；设置中可以另外设定速度上限
3. **挑时间**：登录后等 5 分钟再开始；尽量在锁屏或离开电脑 10 分钟以上时下载和安装；电池供电或按流量计费的网络下不下载
- 提示方式：开始时弹出一条会自动消失的通知"正在后台更新 N 个软件，不影响使用"；托盘显示进度；结束时汇总结果（包括失败项）

### 出错处理
- 记录失败原因（网络、需要重启、安装程序报错、签名不对）；同一个版本最多自动重试 2 次，之后只提醒
- 需要重启的只提示，**绝不自动重启**
- 国内网络：设置中提供"切换 winget 国内镜像源"（默认不改动系统配置，由用户主动开启）

## 7. 卸载器（Geek 式）

1. 运行软件自带的卸载程序（优先使用静默卸载参数；卸载程序缺失或损坏时，提供"强制删除"）
2. 扫描残留：安装目录、`%APPDATA%`、`%LOCALAPPDATA%`、`%PROGRAMDATA%`、注册表（HKCU、HKLM 下的 Software 键）、服务、计划任务、开机自启、快捷方式、右键菜单
3. 用对话框中的表格列出残留：位置 / 类型 / 大小 / 判断，逐项勾选
4. 备份后删除：文件打包、注册表导出，保留 30 天，在"历史"中可以一键恢复

### 判断与默认勾选
| 判断 | 依据 | 默认 |
|---|---|---|
| 确定属于 | 规则 `leftovers.kind: owned`，或者路径等于该软件的安装位置 | 勾选 |
| 可能属于 | 名称或发布者匹配，但缺少其他证据 | 不勾选 |
| 多软件共用 | 其他已安装的软件也引用这个路径（比如 `AppData\Tencent`） | 不勾选 + 黄色警告 |
| 个人数据 | 规则 `kind: personal`（聊天记录、存档、文档） | 不勾选 + 红色警告 |

- 系统目录和系统注册表键在白名单保护之下，永远不会被列为残留
- 如实告知：扫描只能尽量找全，做不到 100%；第二期通过"安装足迹记录"实现精确卸载

## 8. 规则（GKD 式，YAML）

每个软件一个文件，示例：

```yaml
id: kingsoft.wps
name: WPS Office
match:
  displayName: "WPS Office*"
  publisher: "Kingsoft Corp."
update:
  check:                    # 只在云端 CI 中执行，客户端只读取结果
    url: https://…
    extract: '"version":"([\d.]+)"'
  latest:                   # 由 CI 填写
    version: "12.1.0.24000"
    url: https://…
  installer:
    signer: "Zhuhai Kingsoft Office Software Co., Ltd"
    silentArgs: "/S"
  risk: normal              # normal | careful | never-auto
background:
  - task: "WpsUpdate*"
    explain: "WPS 的自动更新任务，登录时和每天运行"
leftovers:
  - path: '%APPDATA%\kingsoft'
    kind: owned             # owned | personal | shared
```

- **客户端不执行任何代码**，也不访问软件官网；`check` 只由官方仓库的 CI 执行（复杂的情况可以用 Python 脚本兜底）
- **订阅**：默认订阅官方源（规则包带签名，防止镜像被篡改）。可以添加第三方源，添加时明确提示"未经审核"；第三方规则不能放宽官方规则中的 `signer`
- 每天同步一次；格式不对的规则跳过并记录，不影响其他规则
- 贡献方式：向 GitHub 官方仓库提交 PR → CI 检查格式并试跑 `check` → 人工审核后合并
- 可疑行为的描述一律使用**中性的事实描述**（比如"开机常驻""自带更新程序"），不给厂商贴"流氓"之类的标签

## 9. 安全模块
- 通过 `root/SecurityCenter2` 查询当前工作的杀毒软件
- 如果是 Defender：一键调用它扫描（快速 / 全盘），并用中文显示结果；隔离和删除都交给 Defender 处理
- 如果是其他杀毒软件：显示"由 XX 保护"，不重复扫描

## 10. 界面
Windows 11 设置风格的外壳 + Geek 风格的紧凑表格（见草图）。页面：首页、更新、我的软件（含卸载对话框）、后台项目（第一期只能查看）、安全、规则订阅、历史（含恢复）、设置。支持深色和浅色主题，使用系统字体。

## 11. 测试
- **单元测试**：版本比较（包括怪格式）、风险判断、规则解析和合并、残留判断和默认勾选、不打扰规则
- **沙盒测试**：安装、更新、卸载只在 Windows 沙盒中进行，使用自制的"假软件"安装包，模拟安装失败、签名不对、残留在共用目录、软件正在运行等情况
- **卸载的硬性要求**：测试必须证明共用目录和个人数据默认不勾选，而且任何删除都能恢复
- 真实系统上只运行只读扫描
